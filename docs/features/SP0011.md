# SP0011 — Ek ister: log zenginleştirme

Durum: ⬜
Task: [T0011_0](../tasks/T0011_0.md)

Bu bir **ek ister** dosyasıdır. SP005 (log altyapısı) geçerliliğini koruyor;
aşağıdakiler onun üzerine gelir.

## Neden

Yeni algoritma, SP005'in ürettiğinden fazlasını istiyor:

- **Bind değerleri.** "Child sorguların bind ettiği FK değerleri birbirinden
  farklı mı?" koşulu, parametre değerlerini görmeyi gerektiriyor. Hibernate
  varsayılan olarak yalnızca `?` basar.
- **Thread bilgisi.** Bind satırları SQL satırından ayrı satırlar hâlinde gelir;
  hangi sorguya ait olduklarını thread üzerinden çözmek gerekir. Paralel
  isteklerde bu olmadan karışırlar.
- **Deterministik sıra.** Algoritma "parent child'dan önce mi çalıştı"
  sorusunu soruyor. Aynı milisaniyeye düşen satırlarda timestamp yetmez.
- **İstek bilgisi.** Rapor endpoint adını istiyor; log satırlarında yok.
- **Zaman aralığı.** Kullanıcı bir aralık seçiyor; log sorgusu correlationId
  değil aralık kabul etmeli.

## İsterler

- SQL parametre değerleri loglanmalı.
- Her log satırı hangi thread'de üretildiğini taşımalı.
- Aynı istek içindeki satırlar deterministik olarak sıralanabilmeli.
- Tamamlanan her istek için endpoint, status ve süre bilgisi sorgulanabilmeli.
- Loglar zaman aralığıyla sorgulanabilmeli.
- Parametre değerleri kişisel veri içerebilir; kimlik numarası gibi alanlar
  loglanmamalı ya da maskelenmeli.

## Kabul kriterleri

- [x] Bind değerleri log satırlarında görünüyor
- [x] Her satırda thread bilgisi var
- [x] Aynı milisaniyedeki satırlar tutarlı sırayla dönüyor
- [x] Tamamlanan istekler endpoint ve süresiyle listelenebiliyor
- [x] Log sorgusu zaman aralığı kabul ediyor
- [ ] Kimlik numarası log'a düşmüyor — **kısmen.** Okuma yolunda (analiz
      senaryosu) hiç düşmüyor; `POST`/`PUT /api/customers` INSERT/UPDATE bind
      parametresi olarak düşüyor. Maskeleme yapılmadı, bilinçli karar
      ([T0011_0 › Kararlar](../tasks/T0011_0.md#kararlar)).
