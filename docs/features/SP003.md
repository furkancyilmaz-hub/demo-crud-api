# F03 — Test verisi

Durum: ✅ yapıldı
Task: [T003_0](../tasks/T003_0.md) · [T003_1](../tasks/T003_1.md)

## Amaç

Performans problemlerinin gerçekten hissedilebileceği büyüklükte, tekrar
üretilebilir bir veri kümesi.

## İsterler

- Veri, uygulama kodunun sorumluluğunda olmamalı.
- Büyüklük: ~5.000 teklif, ~200.000 müşteri, ~600.000 ödeme.
- Müşteri sayısı yüksek olmalı ki indexsiz arama gözle görülür şekilde yavaşlasın.
- **Dağılım heterojen olmalı.** Başvuru başına müşteri ve müşteri başına ödeme
  sayısı sabit olmamalı; 0 ile ~500 arasında değişmeli ki farklı kayıtlar farklı
  N+1 profili üretsin. Her ebeveyne eşit sayıda çocuk verilirse hangi kaydı
  seçersen seç aynı child sorgu sayısını görürsün, ağır/hafif ayrımı yapılamaz.
- Uç vakalar temsil edilmeli: çocuğu olmayan ebeveyn, tek çocuklu ebeveyn,
  yüzlerce çocuklu ebeveyn.
- **Şehir dağılımı yeterince çeşitli olmalı.** Tek şehir sorgusu tüm tablonun
  %1-2'sini geçmemeli; aksi halde index oluşturulsa bile kullanılmaz ve index ekleme fix gibi görünür.
- Veri kümesi her seferinde aynı şekilde yeniden üretilebilmeli.

## Kabul kriterleri

- [x] Kayıt sayıları hedeflenen aralıkta
- [x] Uygulama kodunda veri üretme mantığı yok
- [x] Müşteri/başvuru dağılımı 0-500 aralığında, en az 5 farklı büyüklük kademesi var
- [x] Ödeme/müşteri dağılımı 0-500 aralığında, en az 5 farklı büyüklük kademesi var
- [x] Kasıtlı uç vakalar mevcut: 100 müşterisiz başvuru, 5.000 ödemesiz müşteri
- [x] Tek şehir araması tablonun %2'sinden azını dönüyor
- [x] Üretim süresi dakikalar değil saniyeler mertebesinde
- [x] Sıfırlayıp baştan kurmak aynı sonucu veriyor
