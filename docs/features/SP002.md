# SP002 — PostgreSQL, şema ve compose

Durum: ✅ yapıldı
Repo: demo-api
Bağlı: spec §2, §3

## Ne yapılacak

**Şemanın sahibi SQL scriptidir, Hibernate değil.**

- `db/01-schema.sql` — `CREATE TABLE` ifadeleri ve FK index'leri

`compose.yaml`: tek PostgreSQL servisi, named volume, ve `db/` klasörü
container'ın `/docker-entrypoint-initdb.d/` dizinine mount edilir. Container ilk
kez ayağa kalktığında iki script sırayla çalışır; veritabanı hazır gelir.

`application.yml`'de `ddl-auto: validate`. Hibernate şemayı üretmez, sadece
entity'lerle uyuşup uyuşmadığını doğrular — uyuşmazlık açılışta hata verir.

`spring-boot-docker-compose` bağımlılığı container'ı uygulama ile birlikte başlatır.

Flyway eklenmiyor — demo kapsamı için bilinçli tercih.

## Sıfırlama

Init script'leri yalnızca volume boşken çalışır. Şemayı veya seed'i değiştirdiysen:

```
docker compose down -v && docker compose up -d
```

Bu, demo günü için de temiz bir reset yolu.

## Kararlar

- Seed script (`02-seed.sql`) eklenmedi. Kabul kriterindeki "veri hazır" ifadesi,
  boş ama şeması kurulmuş tablolar olarak yorumlandı; seed verisi bu SP'nin
  kapsamı dışında bırakıldı.
- `docs/01-schema.sql`, `db/01-schema.sql`'e taşındı (dosya sistemi seviyesinde
  kopyalanıp eski dosya silindi — bu ortamda git CLI erişilebilir olmadığından
  `git mv` yerine bu yöntem kullanıldı). Şemanın tek kaynağı artık `db/` altında;
  `docs/` altında ayrı bir kopya yok.
- `compose.yaml`'e `pgdata` named volume'u ve `./db:/docker-entrypoint-initdb.d:ro`
  bind mount'u eklendi. `postgres` image tag'i (`latest`) değiştirilmedi.
- `application.yaml`'de `ddl-auto: none` → `validate` yapıldı, başka anahtar
  değiştirilmedi.
- `postgres:latest` imajı 18+ olduğundan named volume `/var/lib/postgresql/data`
  yerine `/var/lib/postgresql`'e mount edildi (18+'da veri bir üst dizine, sürüme
  özel alt klasörle yazılıyor; eski yol container'ın açılışta exit(1) vermesine
  sebep oldu). Doğrulama sırasında bulundu ve düzeltildi.
