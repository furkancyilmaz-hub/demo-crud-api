   # T04 — İstek korelasyonu

Feature: [SP004](../features/SP004.md) · Repo: demo-api

## Adımlar

1. `common/correlation/CorrelationIdFilter` — `OncePerRequestFilter`.
2. Gelen `X-Correlation-Id` header'ı varsa kullan, yoksa `UUID.randomUUID()`.
3. `MDC.put("correlationId", id)`.
4. Response'a `X-Correlation-Id` yaz.
5. `finally` bloğunda `MDC.remove(...)` — thread havuzda tekrar kullanılıyor,
   temizlenmezse bir sonraki isteğe sızar.
6. Filter'ı en başa al (`@Order(Ordered.HIGHEST_PRECEDENCE)`).

## Doğrulama

```bash
curl -i localhost:8080/customers | grep -i correlation
curl -i -H "X-Correlation-Id: test-123" localhost:8080/customers | grep -i correlation
```

İkincisi `test-123` dönmeli. Peş peşe iki çağrıda kimlikler farklı olmalı.

## Kararlar

- Filter, task'ta önerilen `common/correlation` yerine `filter` paketine
  eklendi: `com.furkan.democrudapi.filter.CorrelationIdFilter`.
- Header/MDC key sabitleri (`X-Correlation-Id`, `correlationId`) ortak bir
  Constants sınıfı açılmadan filter'ın kendi `public static final`
  alanları olarak tutuldu.
- Gelen header boş/whitespace ise (`""`, `"   "`) de yok sayılıp yeni UUID
  üretiliyor (`StringUtils.hasText`).
- Log pattern'ine (`logback-spring.xml`/`application.yaml`) correlationId
  eklenmedi — bilinçli olarak kapsam dışı bırakıldı, MDC'ye yazılması
  yeterli görüldü.
