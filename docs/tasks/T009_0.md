# T009_0 — Senaryo: eksik index

Feature: [SP009](../features/SP009.md) · Repo: demo-api

## Adımlar

1. `application.yml`: `bug.missing-index: true`
2. `GET /customers/search?city=...` — `city` üzerinden filtreleme, sayfalı.
3. `customer.city` şemada indexsiz (F01) → Seq Scan.
4. `internal/InternalToggleController` — `POST /internal/toggle`
   - Gövde: flag adı + açık/kapalı
   - `bug.n-plus-one` → sadece config değeri değişir
   - `bug.missing-index` → kapatılırken `CREATE INDEX idx_customer_city ON customer(city)`,
     açılırken `DROP INDEX IF EXISTS idx_customer_city`
   - `CONCURRENTLY` kullanma (transaction içinde çalışmaz)
   - Index oluşturduktan sonra `ANALYZE customer` çalıştır
5. Yeniden başlatma gerektirmemeli.
6. Bu endpoint agent'ın araçları arasına **girmeyecek** — sadece insan çağırır.

## Doğrulama

```bash
time curl -s "localhost:8080/customers/search?city=Ankara" > /dev/null   # yavaş
curl -X POST localhost:8080/internal/toggle -d '{"flag":"bug.missing-index","enabled":false}'
time curl -s "localhost:8080/customers/search?city=Ankara" > /dev/null   # hızlı
curl -X POST localhost:8080/internal/explain -d "SELECT * FROM customer WHERE city='Ankara'"
# plan Index Scan göstermeli
```

## Tuzaklar

- Index sonrası hâlâ Seq Scan görüyorsan sebep büyük olasılıkla seed'deki şehir
  çeşitliliği (T03 adım 4). Planner az seçici kolonda index kullanmaz.
- `ANALYZE` çalıştırmayı unutma.

## Kararlar

**Endpoint yolu düzeltildi.** Task'taki `localhost:8080/customers/search` bayattı;
`CustomerController` `/api/customers` altında (T008_0'daki aynı hata burada da
tekrarlandı). Gerçek yol `GET /api/customers/search?city=...`.

**Index DDL'i ayrı bir servise (`CustomerIndexService`) taşındı.** `ExplainService`
gibi `JdbcTemplate` kullanıyor. `setMissingIndexEnabled(enabled)` içinde
bug-flag'e bağlı dallanma (create vs drop) servis katmanında — `CustomerService.list()`
içindeki `nPlusOne` dallanmasıyla aynı prensip; `InternalToggleController` sadece
delege ediyor.

**Idempotency guard eklendi.** `enabled` istenen değer zaten mevcut durumla
aynıysa DDL çalıştırılmıyor. Sebep: `CREATE INDEX idx_customer_city` ikinci kez
çağrılırsa "already exists" hatası fırlatır; `DROP INDEX IF EXISTS` kendi başına
idempotent ama simetri için guard her iki yönde de uygulandı.

**`CONCURRENTLY` kullanılmadı**, task'ın istediği gibi — `JdbcTemplate.execute`
çağrıları ayrı ayrı statement olarak çalışıyor, `CREATE INDEX` sonrası `ANALYZE`
sırayla yürütülüyor.

**`BugToggleResponse` iki alanlı oldu:** `nPlusOne` ve `missingIndex` birlikte
dönüyor, `GET /internal/toggle` ve her iki `POST` endpoint'i aynı DTO'yu
kullanıyor — SP009'un "her iki senaryo da aynı kontrol noktasından
yönetilebilmeli" isterini karşılıyor.

**Agent'a kapalı kontrol yüzeyi için ayrı bir mekanizma kurulmadı.** Repo'da
MCP/tool allowlist dosyası yok; `/internal/*` zaten T008_0'da agent'a açık
sayılmayan bir yüzey olarak kabul edilmişti, SP009 bu kararı miras alıyor.

**Canlı doğrulama yapıldı, "Index Scan" beklentisi düzeltildi.** Gerçek Postgres
üzerinde `EXPLAIN (ANALYZE)` çalıştırıldığında planner düz `Index Scan` değil
`Bitmap Heap Scan` + `Bitmap Index Scan(idx_customer_city)` seçti (~2470/200000
satır, planner bu seçicilikte bitmap taramayı tercih ediyor) — yine de index
kullanımı, `Seq Scan` değil. `Execution Time` 39ms'den 3.5ms'e düştü (~11x).
Bug tekrar açıldığında (`enabled=true`) `DROP INDEX IF EXISTS` çalışıp plan
`Seq Scan`'e geri döndü, restart gerekmedi. Aynı `enabled` değeri art arda
gönderildiğinde idempotency guard sayesinde hata (ör. "index already exists")
oluşmadı. `withPayments=false` çıktısı bug açık/kapalı iki durumda da bit bit
aynıydı (`diff` boş).

**Test kapsamı mevcut projenin desenine uydu.** `CustomerController` için ayrı
bir `@WebMvcTest` yok (repo genelinde de yok), bu yüzden `searchByCity` sadece
`CustomerServiceTest` seviyesinde test edildi. `CustomerIndexService` için yeni
`CustomerIndexServiceTest` (`CustomerServiceTest`'teki `@Spy BugProperties`
deseniyle) eklendi. `InternalToggleControllerTest`'te servis mock'landığı için
`BugProperties` mutasyonu `doAnswer` ile simüle edildi.
