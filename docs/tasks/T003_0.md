# T03 — Test verisi

Feature: [SP003](../features/SP003.md) · Repo: demo-api

## Durum

`db/02-seed.sql` **repo'da hazır**. Bu task'ın işi dosyayı yazmak değil,
çalıştığını doğrulamak ve şemayla uyumunu kontrol etmek. Dosyayı gereksiz yere
yeniden yazma.

## Adımlar

1. `db/02-seed.sql`'i gözden geçir; kolon adları `db/01-schema.sql` ile uyuşuyor mu.
2. Her tabloyu **tek statement** ile üret; satır satır INSERT yazma:
   ```sql
   INSERT INTO proposal (proposal_no, status, issue_date, total_premium)
   SELECT 'PRP-' || g, ..., FROM generate_series(1, 5000) AS g;
   ```
3. Customer: 200.000 satır, `proposal_id` mevcut teklifler arasından dağıtılır.
4. **Şehir seçiciliği** — en kritik adım. 80+ elemanlı bir şehir dizisinden rastgele
   seç. Az sayıda şehir kullanırsan tek şehir sorgusu tablonun büyük bölümünü döner,
   planner index'i kullanmaz ve F09 çalışmaz.
5. Payment: ~600.000 satır, her müşteriye 2-4 ödeme. Ödemesiz müşteri kalmasın.
6. Sonda **`ANALYZE proposal; ANALYZE customer; ANALYZE payment;`**
   İstatistikler güncellenmezse planner yanlış plan seçer, F09 tutarsız davranır.

## Doğrulama

```sql
SELECT count(*) FROM customer;                          -- ~200000
SELECT count(*) FROM customer WHERE city = 'Ankara';    -- < 2000 (%1)
SELECT min(c), max(c) FROM (
  SELECT count(*) c FROM payment GROUP BY customer_id) x;  -- min >= 1
```

`docker compose down -v && up -d` → aynı sonuç.

- Seed uzun sürerken Postgres dış bağlantı kabul etmez, bu normal.

## Kararlar

- Statik inceleme: `db/02-seed.sql`'deki kolon adları, enum string'leri
  (`ProposalStatus`/`CustomerStatus`/`PaymentStatus`) ve VARCHAR uzunlukları
  `db/01-schema.sql` ve entity'lerle birebir uyuşuyor. Dosya değiştirilmedi.
- Çalışma zamanı doğrulamasında `payment` INSERT'i **hata verdi**: `date +
  bigint` operatörü yok (`generate_series(1, 2 + (c.id % 3))` ve `c.id % 15`
  ifadeleri `c.id` bigint olduğu için bigint döndürüyor, `DATE + bigint`
  Postgres'te tanımsız). Container init script hatasıyla exit ediyordu.
- Fix: `db/02-seed.sql`'de iki nokta — `generate_series` üst sınırı
  `(2 + (c.id % 3))::int` yapıldı, ve `(c.id % 15)` iki kullanıldığı yerde de
  `::int`'e cast edildi. Mantık/değer aralığı değişmedi (n: 2-4, offset:
  0-14), sadece tip.
- `docker compose down -v && docker compose up -d` ile iki kez sıfırlandı,
  ikisinde de aynı sonuç:
  - `proposal`: 5000, `customer`: 200000, `payment`: 600001
  - `city = 'Ankara'`: 2470 satır (%1,24 — %2 sınırının altında)
  - müşteri başına ödeme: min 2, max 4, ortalama 3.00; ödemesiz müşteri: 0
  - `EXPLAIN ANALYZE` ile `city` sorgusu Seq Scan kullanıyor (index yok,
    F09/SP009 senaryosu için beklenen)
  - Sıfırlamadan container'ın seed'i bitirip ayakta kalmasına kadar geçen
    süre ~18 saniye (dakikalar değil saniyeler)
- Sonuç: kabul kriterlerinin altısı da karşılanıyor, `docs/features/SP003.md`
  buna göre güncellendi.
