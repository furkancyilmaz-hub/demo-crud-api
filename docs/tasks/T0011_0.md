# T0011_0 — Ek ister: log zenginleştirme

Feature: [SP0011](../features/SP0011.md) · Repo: demo-api

## Adımlar

1. **Bind logging** — `application.yml`:
   ```yaml
   logging:
     level:
       org.hibernate.SQL: DEBUG
       org.hibernate.orm.jdbc.bind: TRACE
   ```
   Hibernate 6 için `org.hibernate.orm.jdbc.bind`. Hibernate 5'te karşılığı
   `org.hibernate.type.descriptor.sql.BasicBinder`. Sürümünü kontrol et.
   Üretilen satır: `binding parameter (1:BIGINT) <- [42]`

2. **Şema:** `db/01-schema.sql`'deki `app_log` tablosuna `thread VARCHAR(120)`
   ekle. Sıralama için `id BIGSERIAL` zaten var, tiebreaker olarak kullanılacak.
   Değişiklik sonrası `docker compose down -v && docker compose up -d`.

3. **Appender:** `DbLogAppender` `event.getThreadName()`'i yazsın.
   Appender **senkron** kalsın — asenkron yazımda satır sırası bozulur ve
   `id` tiebreaker'ı anlamını yitirir. Demo yükünde performans sorun değil.

4. **İstek kaydı:** `CorrelationIdFilter` istek tamamlandığında tek satır INFO
   loglasın, sabit formatta:
   ```
   REQUEST_COMPLETED method=GET path=/customers status=200 durationMs=1180
   ```
   Ayrı tablo açma; `app_log` üzerinden sorgulanacak.

5. **`GET /internal/requests?from=&to=`** — o aralıkta tamamlanan istekleri
   döner: `correlationId`, `method`, `path`, `status`, `durationMs`, `timestamp`.
   `REQUEST_COMPLETED` satırlarını ayrıştırarak üretir.

6. **`GET /internal/logs`'a aralık desteği** — mevcut `correlationId`
   parametresi kalsın, ek olarak `from` / `to` (ISO-8601) kabul etsin.
   İkisi de yoksa 400. `limit` üst sınırı 5000'e çıksın, sıralama
   `timestamp, id`.

7. **PII:** `identity_no` bind değeri log'a düşmesin. En basit yol: analiz için
   gerekli olmadığından seed'de `identity_no`'yu WHERE koşullarında kullanmamak.
   Kullanılıyorsa maskele.

## Doğrulama

```sql
SELECT thread, left(message,90) FROM app_log
 WHERE correlation_id='<cid>' ORDER BY timestamp, id LIMIT 30;
```
- SQL satırının hemen ardından `binding parameter …` satırları geliyor
- Hepsi aynı thread'de
- `GET /internal/requests?from=…&to=…` endpoint ve süre dönüyor
- Paralel iki istek at, thread'lerin karışmadığını gör

## Tuzaklar

- Bind logging TRACE seviyesinde ve **çok** satır üretir. Demo için sorun değil;
  üretimde açık bırakılmayacağını sunumda söyle.
- Asenkron appender kullanma. Sıra bozulursa algoritmanın "parent önce mi
  çalıştı" koşulu güvenilmez hale gelir.
- `REQUEST_COMPLETED` formatını değiştirme; agent bunu ayrıştırıyor.

## Kararlar

- **Bind logger:** Hibernate ORM 7.4.1 kullanılıyor → `org.hibernate.orm.jdbc.bind`.
  `BasicBinder` (Hibernate 5) geçerli değil.
- **Appender bağlama:** `logging.level` ayarı tek başına yetmiyor — `DB` appender'ı
  `logback-spring.xml`'de logger'a açıkça bağlı olmak zorunda. Bind logger'ı ve
  `CorrelationIdFilter` için ayrı `<logger>` blokları eklendi. Root'a `DB`
  bağlanmadı: tüm framework/startup logları tabloya akmasın diye.
- **`/internal/**` self-log:** Filter, path `/internal/` ile başlıyorsa
  `REQUEST_COMPLETED` yazmıyor; agent'ın kendi sorguları `/internal/requests`
  sonucunu kirletmiyor. Bu çağrıların Hibernate SQL/bind satırları **hâlâ**
  `app_log`'a düşüyor (elemek thread-local bayrak gerektirirdi) — kabul edilen gürültü.
- **Index:** `idx_app_log_timestamp ON app_log(timestamp, id)` eklendi. Mevcut
  `idx_app_log_correlation`'ın leading kolonu `correlation_id` olduğu için yeni
  saf-aralık sorgularını karşılamıyordu.
- **Parametre doğrulama:** `/internal/logs` için geçerli kombinasyonlar —
  yalnız `correlationId`, yalnız `from`+`to`, ya da üçü birden. Yarım aralık
  (`from` var `to` yok) ve `from > to` reddediliyor. 400 eşlemesi yeni
  `InvalidLogQueryException` + `GlobalExceptionHandler` üzerinden.
- **Limit:** `/internal/logs` üst sınırı 500 → 5000. `/internal/requests`
  task'ta belirtilmemişti; CLAUDE.md "liste dönen sorgular her zaman sayfalanır"
  kuralı gereği `limit` (varsayılan 1000, üst sınır 5000) eklendi.
- **DTO:** `LogEntryResponse`'a `thread` (kabul kriteri) ve `correlationId`
  (aralık sorgusunda satırın hangi isteğe ait olduğu başka türlü bilinemez) eklendi.
- **Test log config:** `src/test/resources/logback-test.xml` eklendi. Olmadan slice
  testler `logback-spring.xml`'i yüklüyor ve `DbLogAppender` her satırda
  "DataSource not ready yet" status hatası basıyordu.
- **PII — kod değişikliği yapılmadı, bilinçli açık:** `identity_no` hiçbir `WHERE`
  koşulunda kullanılmıyor; okuma yolunda (analiz senaryosu) `app_log`'a hiç
  düşmüyor — doğrulandı, 0 satır. Ancak `POST /api/customers` ve
  `PUT /api/customers/{id}` çağrılarının INSERT/UPDATE bind parametresi olarak
  **düşüyor** (doğrulandı: `binding parameter (3:VARCHAR) <- [12345678901]`).
  SP0011'in "kimlik numarası log'a düşmüyor" kriteri yazma endpoint'leri için
  sağlanmıyor; maskeleme yapılmadı, sunumda söylenecek.
